## What is DragonShield?

DragonShield is a **multi-modal counter-UAS (Unmanned Aerial System) platform** that detects, classifies, and tracks unauthorised drones using three independent sensing modalities — RF signal fingerprinting, acoustic signature analysis, and computer vision — fused into a single calibrated threat score via a Bayesian-inspired sensor fusion engine.

```
              RF CLASSIFIER          ACOUSTIC CLASSIFIER        VISUAL TRACKER
              RTL-SDR Dongle         Microphone Array           Camera + YOLOv8
              2.4 / 5.8 GHz         80 Hz – 8 kHz              MOG2 + Kalman
              GBoost · 99.9%        MLP-256 · 98.6%            Multi-Object
                    │                       │                        │
                    └───────────────────────┼────────────────────────┘
                                            ▼
                                   SENSOR FUSION ENGINE
                                   Bayesian Weighted EMA
                                   Conservative Override Rules
                                   False-Positive Filter (3/5 frames)
                                            │
                                            ▼
                                   REAL-TIME DASHBOARD
                                   FastAPI + WebSocket
                                   Live Threat Assessment
```

## ⚠️ Honesty: What is Real vs Synthetic

This section exists because it matters — both for academic integrity and for real deployment decisions. Everything in the codebase is computationally genuine, but the data the models were trained on is fully synthetic.

### RF Classifier — Synthetic Training Data

**What is real:**
- The feature engineering pipeline is real signal processing: Welch PSD, spectral centroid/spread/flatness, 8 sub-band energies, FHSS hopping score from chunk-wise FFT variance, cyclostationary autocorrelation features. These are the same features used in published RF drone fingerprinting research.
- The model is a real GradientBoosting classifier. It was trained, evaluated, and cross-validated using scikit-learn. 99.9% CV accuracy is genuine — but see below.
- `RTLSDRInterface` contains real hardware code: when `pyrtlsdr` is installed and a dongle is plugged in, it reads actual IQ samples from the air and runs the same feature extraction pipeline.

**What is synthetic:**
- **The training dataset is entirely synthetic.** `SyntheticRFDataGenerator` constructs IQ signals mathematically — OFDM-like multi-carrier signals for DJI, frequency-hopping sequences for FPV, bursty patterns for WiFi drones, flat noise for background, pseudo-random for "military/encrypted". No real RF captures were collected.
- The 99.9% CV accuracy is therefore **accuracy on synthetic test data generated by the same distribution as the training data.** It does not represent performance on real-world RF captures, which would include multipath, co-channel interference, real modulation imperfections, and unknown drone models.
- In a real deployment, this model would need to be retrained or fine-tuned on actual RTL-SDR captures. The architecture and features are production-appropriate; the learned weights are proof-of-concept.

### Acoustic Classifier — Synthetic Training Data

**What is real:**
- The feature extraction is real digital signal processing: a from-scratch MFCC implementation (mel filterbank, framing, hamming window, DCT), plus harmonic analysis that directly exploits the physics of drone rotors (f₀ = N_blades × RPM / 60 Hz). The 71-dimensional feature vector (20 MFCCs × mean/std/delta + 11 harmonic features) is sound signal processing practice.
- The model is a real sklearn MLP (256→128→64) with early stopping and proper train/test splits.
- `MicrophoneStream` contains real hardware code: when `pyaudio` is installed, it reads live mic input and classifies continuously in a background thread.

**What is synthetic:**
- **The training dataset is entirely synthetic.** `SyntheticAudioGenerator` produces drone sounds by summing harmonic sinusoidal series at physically-motivated fundamentals: small quadcopter ~90–150 Hz, FPV racer ~200–350 Hz, hexacopter ~45–75 Hz, helicopter ~10–25 Hz main rotor + 6× tail rotor, etc. Noise is additive Gaussian.
- The 98.6% accuracy is **accuracy on synthetic test audio generated from the same parametric model as training.** A real microphone recording of a DJI Mini 3 would sound similar but not identical — real drones have motor cogging, prop wash turbulence, asymmetric loading, and acoustic coupling between frame and propellers that the synthetic model does not capture.
- As with RF: the architecture, features, and physics-based design are production-appropriate. The trained weights need real data to be operationally valid.

### Visual Tracker — Partially Real

**What is real (all of this runs on actual pixels):**
- MOG2 background subtraction (`cv2.createBackgroundSubtractorMOG2`) is a real OpenCV algorithm operating on real video frames — it genuinely detects moving foreground objects via adaptive Gaussian mixture models.
- The Kalman filter tracker is a real implementation: state vector `[cx, cy, vx, vy]`, transition matrix F, observation matrix H, process noise Q, measurement noise R. It runs on real bounding box centroids from detected contours.
- When `ultralytics` is installed, YOLOv8n runs real inference — it uses pretrained COCO weights by default, and can be fine-tuned on drone datasets.
- The full video upload pipeline (browser → `/api/process-frame` → OpenCV → MOG2 → Kalman → JSON response) is end-to-end real and runs on real footage.

**What is limited:**
- The base YOLOv8n weights are pretrained on COCO (general objects). Drone-specific fine-tuning requires a labelled drone video dataset, which has not been done here. MOG2 will detect any moving object — it does not distinguish drones from birds or aircraft without classification.
- Distance estimation uses a pinhole camera model with assumed focal length and drone size — it is a reasonable estimate, not a calibrated measurement.

### Sensor Fusion Engine — Real Algorithm, Simulated Inputs

The fusion logic is genuine: adaptive confidence weighting, EMA smoothing (α = 0.30), conservative override rules, and a 3-of-5 frame majority vote filter before raising an alarm. This logic is sound and production-applicable.

When running without real hardware, all three sensor inputs come from their respective synthetic generators, so the fusion output is also synthetic. The architecture is correct; the scenario shown is a simulation.

### Dashboard / Web UI — Real Infrastructure

The FastAPI server, WebSocket streaming, video frame processing endpoint, and browser UI are real working code. The "no webcam on startup" behaviour, the three-button source selector (Demo / Webcam / Upload), and the real-time detection pipeline when uploading footage are all functional.

## Quick Start

### 1. Install dependencies

```bash
git clone https://github.com/yourusername/dragonshield.git
cd dragonshield
pip install -r requirements.txt
```

Minimum install (no hardware, simulation mode):
```bash
pip install fastapi "uvicorn[standard]" websockets opencv-python scikit-learn numpy scipy aiofiles
```

### 2. Train the models

```bash
python train_models.py
```

This generates `models/rf_model.pkl` and `models/audio_model.pkl` from synthetic data. Accuracy figures printed here are on the synthetic test split — see the honesty section above.

### 3. Launch the dashboard

```bash
python run.py
# Open http://localhost:8000
```

On the video panel you will see three options:

| Button | What it does |
|---|---|
| **▶ DEMO VIDEO** | Plays the built-in pre-recorded footage with live MOG2+Kalman detection |
| **◉ OPEN WEBCAM** | Starts the server-side camera — only activates when you click it |
| **⬆ UPLOAD VIDEO** | Run detection on your own MP4 / MOV / AVI / WEBM footage |

Nothing opens automatically. No webcam starts until you ask for it.

## Architecture

### Module 1 — RF Signal Classifier (`src/rf_classifier/`)

Identifies drone types by their radio frequency emission signatures.

- **Hardware target**: RTL-SDR Blog V3 dongle, 2.4 GHz and 5.8 GHz bands
- **Features**: 20-dimensional spectral vector — centroid, spread, flatness, 8 sub-band energies, FHSS hopping score (variance of per-chunk FFT peak locations), burst rate (zero-crossing proxy), 4 cyclostationary autocorrelation lags
- **Model**: GradientBoosting (200 estimators, depth 5, lr 0.08, subsample 0.85)
- **Classes**: BACKGROUND, DJI Phantom, DJI Mini, DJI FPV, Generic RC 2.4 GHz, FPV 5.8 GHz, WiFi drone, Military/Encrypted
- **Training data**: Synthetic IQ from `SyntheticRFDataGenerator` (see honesty section)
- **CV accuracy**: 99.9% on synthetic test set
- **Fallback**: Same synthetic generator runs at inference time when no dongle present

### Module 2 — Acoustic Classifier (`src/audio_classifier/`)

Detects drone motor and propeller acoustic signatures.

- **Hardware target**: Any USB microphone, effective range ~80 m quiet / ~30 m urban
- **Features**: 20 MFCCs (mean + std + delta) + 11 harmonic features (f₀, harmonic ratio, rotor centroid, ZCR, RMS, 6 harmonic band energies) = 71-dimensional vector
- **Model**: sklearn MLP (256→128→64, ReLU, early stopping, val split 15%)
- **Classes**: BACKGROUND, Small/Large Quadcopter, Hexacopter, FPV Racing, Fixed Wing, Helicopter
- **Training data**: Synthetic audio from `SyntheticAudioGenerator` using physics-based harmonic series models (see honesty section)
- **Accuracy**: 98.6% on synthetic test set
- **Fallback**: Same synthetic generator runs in a background thread when no mic present

### Module 3 — Visual Tracker (`src/visual_tracker/`)

Detects and tracks drones in video using deep learning + classical filtering.

- **Primary detector**: YOLOv8n (COCO pretrained; replace with drone-specific fine-tuned weights for production use)
- **Fallback detector**: MOG2 background subtraction — detects any moving foreground object
- **Tracker**: Kalman filter (state: `[cx, cy, vx, vy]`, process noise Q = diag[1,1,5,5], measurement noise R = diag[4,4]) + IoU-based multi-object assignment
- **Outputs**: Bounding boxes, trajectory tail, velocity vector, heading estimate, distance estimate (pinhole camera model), per-track threat score
- **Input**: Webcam, uploaded video file, or WebSocket-streamed frames

### Module 4 — Sensor Fusion Engine (`src/sensor_fusion/`)

Fuses all three sensor streams into one calibrated threat assessment.

```
Fused Score = Σ (base_weight_i × confidence_i × sensor_score_i)   [weights renormalised to sum=1]
            ↓ EMA smoothing   (α = 0.30)
            ↓ Conservative override  (any sensor > 0.90 at > 0.75 confidence → CRITICAL)
            ↓ False-positive filter  (3 / 5 frame majority vote before alarm raised)
```

Weights are adaptive: sensors with higher confidence on the current frame dominate. Inactive sensors get weight = 0 (redistributed to active sensors). Threat levels: `CLEAR → LOW → MEDIUM → HIGH → CRITICAL`.

### Module 5 — Dashboard (`src/dashboard/`)

FastAPI WebSocket server streaming live telemetry to the browser UI.

```
GET   /               → dashboard HTML
GET   /api/status     → system health, uptime, alarm count
GET   /api/telemetry  → latest sensor readings (JSON)
GET   /api/logs       → server-side log buffer
WS    /ws             → live stream at 500 ms interval
POST  /api/process-frame   → analyse a single video frame (base64 JPEG → detections)
POST  /api/reset-processor → reset MOG2 background model for new video
POST  /api/camera/start    → open webcam (called when user clicks ◉ OPEN WEBCAM)
POST  /api/camera/stop     → release webcam
```

## The Path to a Real System

For a deployable operational system, the key remaining work is:

1. **Collect real RF captures.** Record IQ samples from actual drone flights (DJI Mini 3, Phantom 4, FPV builds) with an RTL-SDR dongle. Retrain the GBoost classifier on this data. The feature pipeline stays the same.

2. **Collect real acoustic recordings.** Record drones at known distances with a USB microphone in varied environments. The MFCC + harmonic pipeline stays the same; the MLP needs real training data.

3. **Fine-tune YOLOv8 on a drone dataset.** Public datasets: `drone-detection` on Roboflow, AU-AIR, or collect and label your own footage. Export to TensorRT for Jetson deployment.

4. **RTL-SDR direction finding.** Add a second antenna and measure phase difference to estimate bearing. Two units give triangulation.

5. **GPS / ADS-B integration.** Correlate visual + RF tracks with ADS-B feed to auto-discriminate manned aircraft.
